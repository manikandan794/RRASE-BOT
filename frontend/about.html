Project Status

Every feature below has working backend code, a database migration, and (where it's meaningfully testable offline) an automated test. Items marked "needs live setup" are fully implemented but require a real environment - a running Ollama install, a PostgreSQL server, or network access to rrase.com - to actually produce answers.

Implemented

  • JWT authentication, bcrypt password hashing, role-based access control (Student / Faculty / Admin / Principal)
  • Student self-registration; admin-managed staff (faculty/admin/principal) account creation
  • Full CRUD management for College Info, Departments, Faculty, Courses, FAQs, Notices, Events, Facilities, Contacts
  • PDF upload → text extraction → chunking → embedding → persistent vector store (Chroma)
  • Official website import → extract → clean → admin/principal review → approve → knowledge base
  • AI Provider abstraction: Ollama (primary) → Gemini (optional fallback) → graceful "unavailable" - never fabricates college facts
  • Database/FAQ-first chat pipeline with RAG fallback, chat history, thumbs up/down feedback, and unanswered-question logging
  • Admin, Principal, and Faculty dashboards (the Faculty view is read-only by design)
  • Analytics summary, audit logging of every admin/principal action, in-memory rate limiting, upload/file validation
  • Automated tests: auth/RBAC, chunking, and the full chat decision pipeline (with AI calls mocked so tests run offline)
  • Alembic migrations for the entire schema, Docker Compose, an example Nginx config, and HTTPS/subdomain deployment docs

Needs a live environment to fully activate

  • Ollama must be installed and running with a pulled model (e.g. ollama pull llama3.1 and ollama pull nomic-embed-text) for AI-generated answers and embeddings
  • Gemini fallback only activates if GEMINI_API_KEY is set - it's optional
  • PostgreSQL must be running and migrated (alembic upgrade head) before the API will serve real data
  • Website import needs outbound network access to rrase.com from wherever the backend runs
  • Official branding (logo, exact colors) - the current theme is a placeholder until the college supplies brand assets

Design principles this project follows

  • Database/FAQ is always checked before any AI call - the AI is never the first thing asked
  • Website content is never trusted automatically - it sits in a pending queue until a human approves it
  • The AI is always given retrieved context and told to say "I don't know" rather than invent college-specific facts
  • No AI provider is hard-coded into the application logic - swapping or adding providers means writing one class
